# Documentation Internationalization (i18n) Convention

[English](i18n.md) | [简体中文](../zh-CN/i18n.md)

> This document defines the bilingual (English / Simplified Chinese) convention
> for all documentation in this repository. Apply this to every new doc, every
> PR, and every cleanup pass.

## 1. Scope

- **Bilingual target**: English (default) + Simplified Chinese (`zh-CN`).
- **Every doc** in `docs/`, every `README.md` in workspace, every crate-level
  `README.md`, and the OpenAPI spec must follow this convention.
- **Symmetric subdirectories**: each supported language gets its own
  subdirectory under `docs/`. English lives in `docs/en/`, Simplified
  Chinese in `docs/zh-CN/`. Future locales (e.g. `de/`, `ja/`, `fr/`) slot
  in the same way.
- **Why English first** within a subdirectory: `docs/en/<name>.md` is the
  source of truth; Chinese is in a parallel `docs/zh-CN/<name>.md`.

## 2. File naming + directory structure

| File path                          | Language     | Role                                  |
|-----------------------------------|--------------|---------------------------------------|
| `docs/en/<name>.md`               | English      | canonical / default                   |
| `docs/zh-CN/<name>.md`            | Chinese      | translation in a dedicated subdir     |
| `docs/en/api/openapi.json`        | English      | OpenAPI English version               |
| `docs/zh-CN/api/openapi.json`     | Chinese      | OpenAPI Chinese version               |
| `crates/<crate>/README.md`        | English      | crate README (single file)            |
| `crates/<crate>/README.zh-CN.md`  | Chinese      | crate README Chinese (sibling file)   |
| `docs/<lang>/<name>.md`           | Other locale | future locales (`lang` = RFC 5646 tag) |

**Symmetric subdirectory split** for `docs/`:

- Pros: 35+ documents don't pollute the `docs/` root (only `mkdocs.yml` lives there)
- Pros: each language directory is managed independently
- Pros: adding a new locale is a 1-step `mkdir docs/<lang>/` + translate
- Pros: mkdocs-material `i18n` plugin + `alternate_language` work out of the box
- Cons: cross-language link maintenance requires `../en/<name>.md` (or
  `../zh-CN/<name>.md`) — explicit two-level climb
- Cons: GitHub doesn't auto-switch by `Accept-Language` (needs `?lang=zh-CN` query or README link)

**Why keep Tier-2 docs (weekly/, reports/) in `docs/zh-CN/` instead of `docs/`?**

- They are historical reports / weekly logs, primarily for the project's
  internal audience
- `weekly/` is planned to become truly bilingual (P13 task: translate
  Chinese → English into `docs/weekly/`); for now only the Chinese version
  exists, so the English directory is the "to be filled" counterpart.
- `reports/` is Chinese-only for now; each file gets a `coming soon` banner
  and a placeholder link to a future English version.
- Keeping them in `docs/zh-CN/` makes them obvious to Chinese readers;
  when an English version is ready, move it (or its translation) up to
  `docs/` (or `docs/reports/` for symmetry).

## 3. Top-of-file language banner

Every translated file starts with a banner linking the other language:

**English file** (`docs/en/<name>.md`):

```markdown
# Title

[English](<name>.md) | [简体中文](../zh-CN/<name>.md)

> Brief description.
```

**Chinese file** (`docs/zh-CN/<name>.md`):

```markdown
# 标题

[English](../en/<name>.md) | [简体中文](<name>.md)

> 简介.
```

**Banner rules**:
- First line: title
- Second line: language switcher link
- English file links to `../zh-CN/<name>.md` (up one to `docs/`, then into `zh-CN/`)
- Chinese file links to `../en/<name>.md` (up one to `docs/`, then into `en/`)

## 4. Translation rules

### 4.1 Terminology

| English              | Chinese (zh-CN)        | Notes                          |
|----------------------|------------------------|--------------------------------|
| workspace            | workspace              | Borrowed; no translation       |
| crate                | crate                  | Borrowed; no translation       |
| conformance          | conformance (一致性测试) | First occurrence parenthetical |
| plugin               | plugin (插件)          | First occurrence parenthetical |
| bundle / manifest    | bundle / manifest (清单) | First occurrence parenthetical |
| artifact             | artifact (产物)        | First occurrence parenthetical |
| registry             | registry (注册表)      | First occurrence parenthetical |
| event                | event (事件)           | First occurrence parenthetical |
| session              | session (会话)         | First occurrence parenthetical |
| agent                | agent (智能体)         | First occurrence parenthetical |
| LLM / model          | LLM / model (大模型)   | First occurrence parenthetical |

After the first occurrence, drop the parenthetical. Code identifiers, paths,
URLs, and CLI commands are never translated.

### 4.2 Code blocks

- Code blocks (fenced) are **never translated** — keep them identical in both
  languages.
- Inline `code` is also never translated.
- File names, function names, type names, etc. are never translated.

### 4.3 Links

- Cross-doc links within the same language: `[X](<name>.md)` (relative path
  inside the same `docs/<lang>/` directory).
- Cross-language links: `[English](../en/<name>.md)` or
  `[简体中文](../zh-CN/<name>.md)` (climb out of current language dir, then
  descend into the other one).
- External links (GitHub, crates.io, etc.) are language-neutral.

### 4.4 Versioning

When updating a doc:

1. Update the English version first (it is the source of truth).
2. Mirror the change in the Chinese version.
3. If the Chinese version lags behind, add a footer note in the Chinese file:
   `> 本文档可能落后于英文版本. 最后同步: YYYY-MM-DD.`

## 5. What is in scope for bilingual support

### Tier 1 (must be bilingual) — currently covered

- `docs/en/README.md` (English) + `docs/zh-CN/README.md` (Chinese)
- 8 core design docs in `docs/en/` (see `docs/en/README.md` index)
- 8 crate READMEs (each `crates/*/README.md` has a `.zh-CN.md` sibling)
- `docs/en/api/openapi.json` (English) + `docs/zh-CN/api/openapi.json` (Chinese)

### Tier 2 (Chinese-only for now, lives in `docs/zh-CN/`)

- `docs/zh-CN/weekly/*.md` — weekly dev logs (P13 plan: translate to
  `docs/en/weekly/*.md` to make this folder truly bilingual)
- `docs/zh-CN/reports/*.md` — milestone reports and historical docs:
  - `p11-baseline-report.md`, `p11-final-report.md`, `p12-final-report.md` — phase wrap-up
  - `dsh-benchmark-report.md` — dsh equivalence report
  - `benchmark-report-week11.md` — perf baseline
  - `conformance-report-week11.md` — conformance baseline
  - `pyo3-evaluation.md` — tech evaluation
  - `code-mode-deferred.md` — tech decision
  - `roadmap-phase-7.md`, `roadmap-phase-11.md` — historical roadmaps
- `docs/zh-CN/decision-log.md` — decision log (largest doc, 1500+ lines;
  split into 4 phase parts + master TOC in commit 6b1018d)

These get a top-of-file banner:

For a Tier-2 doc in `docs/zh-CN/`:

```markdown
# Title (中文 / Chinese only)

[English](../en/<name>.md) — coming soon. 中文为主.

> (content)
```

For a Tier-2 doc inside the `docs/zh-CN/reports/` subdirectory, the
English path needs to climb two extra levels (out of `reports/`, then out
of `zh-CN/`):

```markdown
# Title (中文 / Chinese only)

[English](../../zh-CN/reports/<name>.md) — coming soon. 中文为主.

> (content)
```

(English counterpart, when published, lives at `docs/en/<name>.md`. For
`reports/` content, the English version would go to `docs/en/reports/<name>.md`.)

When translating, create `docs/en/<name>.md` (English) and update the
Chinese banner; remove the "coming soon" marker.

## 6. OpenAPI spec

`docs/en/api/openapi.json` and `docs/zh-CN/api/openapi.json` are kept as two
**independent** files (not a single bilingual spec). Rationale:

- OpenAPI tooling (Swagger UI, Redoc, code generators) expects a single locale
  per spec.
- Bilingual in a single `description` field hurts grep-ability and tooling.
- Two files share the same structure; descriptions differ only by language.

The CLI command `mah open-api export` regenerates the English spec. The Chinese
spec is generated by a separate script (planned P13) that translates the
`summary` / `description` fields.

## 7. mkdocs config

`docs/mkdocs.yml` lists all English docs under `nav`. mkdocs-material's
`alternate_language: zh-CN` + `extra.alternate` automatically picks up the
`docs/zh-CN/` subdirectory. Top navigation in every page includes a language
switcher (header top-right).

```yaml
theme:
  alternate_language: zh-CN
extra:
  alternate:
    - name: English
      link: /en/
      lang: en
    - name: 简体中文
      link: /zh-CN/
      lang: zh-CN
```

Business runs: `pip install mkdocs-material[i18n]` then `cd docs && mkdocs serve`.

## 8. PR / contribution checklist

When adding or updating a doc:

- [ ] English file `docs/en/<name>.md` — **source of truth**
- [ ] Chinese file `docs/zh-CN/<name>.md` — translation
- [ ] Top-of-file language banner present in BOTH files
- [ ] Code blocks, paths, identifiers are identical in both
- [ ] Cross-doc links point to the matching language
- [ ] `docs/en/README.md` index updated (if adding a new doc)
- [ ] `docs/zh-CN/README.md` index updated (if adding a new doc)
- [ ] mkdocs.yml nav updated (if adding a new doc)

## 9. Examples

### Good — Tier 1 bilingual pair

```text
docs/en/conformance-design.md         (English, source of truth)
docs/zh-CN/conformance-design.md      (Chinese, translation)
```

Both files start with:

**English** (`docs/en/conformance-design.md`):
```markdown
# Conformance Test Design

[English](conformance-design.md) | [简体中文](../zh-CN/conformance-design.md)
```

**Chinese** (`docs/zh-CN/conformance-design.md`):
```markdown
# Conformance Test Design (中文 / 简体中文)

[English](../en/conformance-design.md) | [简体中文](conformance-design.md)
```

### Good — Tier 2 (Chinese-only for now)

In `docs/zh-CN/reports/conformance-report-week11.md`:

```markdown
# Week 11 Conformance Report (中文 / Chinese only)

[English](../../en/reports/conformance-report-week11.md) — coming soon. 中文为主.

> 本文档记录 Week 11 的 conformance 跑分.
```

### Bad — naming inconsistency

```text
# Bad: same-directory approach (legacy)
docs/en/conformance-design.zh-CN.md

# Bad: wrong subdirectory
docs/cn/conformance-design.md
```
