# Plugin Registry on GitHub Pages (P14)

> **Status**: P14 (2026-08-20) wired up. CI workflow ready; needs one-time GitHub Pages setup.

This document describes how `ma-harness.rs` publishes its Plugin Registry
to a static site on GitHub Pages, so plugin authors can browse and
install third-party plugins.

## One-time setup (business side)

1. **GitHub repo settings**:
   - Go to https://github.com/ma-harness/ma-harness.rs/settings/pages
   - **Source**: "GitHub Actions" (NOT "Deploy from a branch")
   - This unlocks the `actions/deploy-pages` workflow to publish

2. **Gitee mirror** (optional, China users):
   - Gitee Go also has Pages support but requires manual approval
   - For now, the workflow only deploys to GitHub Pages
   - If Gitee Pages is enabled, you can extend the workflow to mirror

## How it works

```
business author writes plugin.toml
  ↓
mah plugin publish plugin.toml   # writes to ~/.ma-harness/registry.json
  ↓
business commits registry.json to docs/registry/registry.json
  ↓
git push to main
  ↓
.github/workflows/registry-pages.yml triggers
  ↓
build job: install mah CLI, generate static index.html
  ↓
deploy job: actions/deploy-pages publishes to gh-pages branch
  ↓
https://ma-harness.github.io/ma-harness.rs/registry/
```

## Local usage

### List plugins

```bash
$ mah registry list
ma-harness Plugin Registry
============================
Path:   /home/user/.ma-harness/registry.json
Plugins: 3 (5 versions total)

i25ma (3):
  - hello-plugin @ 0.1.0 (tags: demo, tutorial)
  - mah-py-bridge @ 0.2.1 (tags: python, sdk)
  - custom-tool-fs @ 1.0.0 (tags: filesystem, sandbox)
```

### Export to JSON

```bash
$ mah registry export --output docs/registry/registry.json
Exported 3 plugins (5 versions) to docs/registry/registry.json
```

### Custom registry path

```bash
# Use a different registry file
$ mah registry list --registry /path/to/registry.json
$ mah registry export --registry /path/to/registry.json --output out.json
```

## Adding a new plugin

### 1. Write `plugin.toml`

```toml
[plugin]
name = "my-cool-plugin"
version = "0.1.0"
description = "Does cool things"
author = "your-name"
source = { type = "local", path = "../plugins/my-cool-plugin" }
tags = ["category", "feature"]
```

### 2. Publish locally

```bash
$ mah plugin publish plugin.toml
Published my-cool-plugin @ 0.1.0 to /home/user/.ma-harness/registry.json
```

### 3. Commit to repo

```bash
# Export the local registry to docs/registry/registry.json
$ mah registry export --output docs/registry/registry.json

# Commit + push
$ git add docs/registry/registry.json
$ git commit -m "feat(registry): publish my-cool-plugin @ 0.1.0"
$ git push origin main
```

The `registry-pages.yml` workflow will:
1. Detect the change to `docs/registry/registry.json`
2. Rebuild the static site
3. Deploy to GitHub Pages

Within ~2 minutes, your plugin appears at:
`https://ma-harness.github.io/ma-harness.rs/registry/`

## Install a plugin

```bash
# Once registry is published
$ mah plugin install my-cool-plugin@0.1.0
Installed my-cool-plugin @ 0.1.0 to ~/.ma-harness/plugins/

# Or install latest
$ mah plugin install my-cool-plugin
```

## Workflow file: `.github/workflows/registry-pages.yml`

The workflow:
- Triggers on push to `main` (when `docs/registry/**` or workflow file changes)
- Supports `workflow_dispatch` (manual trigger for testing)
- Builds the static site in a `build` job
- Deploys via `actions/deploy-pages@v4` in a `deploy` job
- Uses `concurrency: pages` to avoid concurrent deploys

The static `index.html` is generated by the workflow itself (no Jekyll/Hugo
needed). The registry JSON is copied as `registry.json` for programmatic
consumption.
