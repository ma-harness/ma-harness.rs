# 文档国际化 (i18n) 规范

[English](i18n.md) | [简体中文](i18n.zh-CN.md)

> 本文档定义本仓库所有文档的双语 (英文 / 简体中文) 规范.
> 每个新文档, 每个 PR, 每次清理都要遵守.

## 1. 范围

- **双语目标**: 英文 (默认) + 简体中文 (`zh-CN`).
- **每个文档** 在 `docs/`, workspace 里每个 `README.md`, 每个 crate 级别的
  `README.md`, 以及 OpenAPI spec, 都要遵守本规范.
- **英文优先原因**: GitHub 自动检测 `*.md` (英文) 跟 `*.zh-CN.md` (中文)
  (基于 viewer 浏览器 `Accept-Language` 头). 源真值 (source of truth) 是英文.

## 2. 文件命名

| 文件名格式            | 语言     | 角色                                  |
|----------------------|----------|---------------------------------------|
| `name.md`            | 英文     | 标准 / 默认                           |
| `name.zh-CN.md`      | 中文     | 同内容翻译                            |
| `name.zh-CN.md.json` | (n/a)    | 预留 (部分静态站点用)                 |
| `name.<other>.md`    | 其他 locale | 未来 locale (de, ja, fr, ...)       |

**两个文件同目录** (不要拆成 `docs/` + `docs/zh-CN/`).
GitHub 按 viewer 浏览器语言自动展示.

### 示例

```text
docs/README.md                # 英文索引
docs/README.zh-CN.md          # 中文索引
crates/ma-harness-core/README.md      # 英文 crate README
crates/ma-harness-core/README.zh-CN.md # 中文 crate README
docs/api/openapi.json         # 英文 OpenAPI
docs/api/openapi.zh-CN.json   # 中文 OpenAPI
```

## 3. 文件顶部语言条

每个翻译文件都以语言条开头:

```markdown
# 标题

[English](name.md) | [简体中文](name.zh-CN.md)

> 简介.
```

**语言条规则**:
- 第一行: 标题
- 第二行: 语言切换链接, 紧跟标题
- 链接文字必须跟文件语言匹配 (e.g. 在 `.zh-CN.md` 文件, 链接文字是
  `[English](name.md)`; 在英文文件是 `[简体中文](name.zh-CN.md)`).

## 4. 翻译规则

### 4.1 术语表

| 英文              | 中文 (zh-CN)        | 备注                          |
|------------------|---------------------|------------------------------|
| workspace        | workspace           | 借用词, 不译                  |
| crate            | crate               | 借用词, 不译                  |
| conformance      | conformance (一致性测试) | 首次出现加括号              |
| plugin           | plugin (插件)       | 首次出现加括号                |
| bundle / manifest | bundle / manifest (清单) | 首次出现加括号            |
| artifact         | artifact (产物)     | 首次出现加括号                |
| registry         | registry (注册表)   | 首次出现加括号                |
| event            | event (事件)        | 首次出现加括号                |
| session          | session (会话)      | 首次出现加括号                |
| agent            | agent (智能体)      | 首次出现加括号                |
| LLM / model      | LLM / model (大模型) | 首次出现加括号               |

首次出现后, 去掉括号. 代码标识符, 路径, URL, CLI 命令永不翻译.

### 4.2 代码块

- 代码块 (fenced) **永不翻译** — 两个语言保持完全一致.
- 行内 `code` 也不翻译.
- 文件名, 函数名, 类型名等不翻译.

### 4.3 链接

- 文档间链接: 英文文件用 `[X](other.md)`, 中文文件用 `[X](other.zh-CN.md)`.
- 外部链接 (GitHub, crates.io 等) 语言中立.

### 4.4 版本同步

更新文档时:

1. **先更新英文版** (源真值).
2. 同步改动到中文版.
3. 如果中文版滞后 (e.g. 只有一个翻译者), 在中文版加 footer:
   `> 本文档可能落后于英文版本. 最后同步: YYYY-MM-DD.`

## 5. 双语范围

### Tier 1 (必须双语) — 当前已覆盖

- `README.md` (根, 英文) + `README.zh-CN.md` (根, 中文)
- `docs/` 里 7 个核心设计文档 (见 `docs/README.md` 索引)
- 8 个 crate README (每个 `crates/*/README.md` 都有 `.zh-CN.md` 副本)
- `docs/api/openapi.json` (英文) + `docs/api/openapi.zh-CN.json` (中文)

### Tier 2 (当前中文为主, 标 "EN coming soon")

- `docs/weekly/*.md` — 周开发日志
- `docs/p11-*.md`, `docs/p12-*.md` — 里程碑报告
- `docs/dsh-benchmark-report.md` — dsh 等价报告
- `docs/benchmark-report-week11.md` — perf baseline
- `docs/conformance-report-week11.md` — conformance baseline
- `docs/pyo3-evaluation.md` — 技术选型
- `docs/code-mode-deferred.md` — 技术决策
- `docs/roadmap-phase-7.md`, `docs/roadmap-phase-11.md` — 历史路线

这些文件加顶部标记:

```markdown
# 标题 (中文 / Chinese only)

[English](name.md) — coming soon. 中文为主.

> (内容)
```

翻译时拆成 `name.md` (英文) + `name.zh-CN.md` (中文), 删掉 "coming soon" 标记.

## 6. OpenAPI spec

`docs/api/openapi.json` 跟 `docs/api/openapi.zh-CN.json` 是**独立两份** (不是单文件双语).
原因:

- OpenAPI 工具 (Swagger UI, Redoc, 代码生成器) 期望单语言 spec.
- 单文件双语 `description` 字段难 grep, 难工具化.
- 两份文件结构相同; 只 `summary` / `description` 不同.

CLI 命令 `mah open-api export` 重新生成英文 spec.
中文 spec 由独立脚本生成 (P13 计划) 翻译 `summary` / `description` 字段.

## 7. mkdocs 配置

`docs/mkdocs.yml` 把所有英文 doc 列在 nav 里. 中文对应 (`.zh-CN.md`) 同目录,
mkdocs 通过 `i18n` plugin 收集 (见 mkdocs-material `i18n` feature). 每个页面
顶部导航带语言切换器.

## 8. PR / 贡献 checklist

添加或更新文档时:

- [ ] 文件名 `name.md` (英文) — **源真值**
- [ ] 副本 `name.zh-CN.md` (中文) — 翻译
- [ ] 两个文件顶部都有语言条
- [ ] 代码块, 路径, 标识符在两个文件完全相同
- [ ] 跨文档链接指向对应语言
- [ ] `docs/README.md` 索引更新 (如果新增文档)
- [ ] mkdocs.yml nav 更新 (如果新增文档)
- [ ] (如果只更新一种语言) PR 描述注明语言滞后跟目标同步日期

## 9. 示例

### 好 — 双语对

```text
docs/conformance-design.md         (英文, 源真值)
docs/conformance-design.zh-CN.md   (中文, 翻译)
```

两个文件都以:

```markdown
# Conformance Test Design

[English](conformance-design.md) | [简体中文](conformance-design.zh-CN.md)
```

开头.

### 好 — Tier 2 (当前中文为主)

```markdown
# Week 11 Conformance Report (中文 / Chinese only)

[English](conformance-report-week11.md) — coming soon. 中文为主.

> 本文档记录 Week 11 的 conformance 跑分.
```

### 差 — 命名不一致

```text
# 差: 拆成子目录
docs/zh-CN/conformance-design.md
docs/conformance-design.md

# 差: locale 写错 (应该是 zh-CN 不是 zh)
docs/conformance-design.zh.md
```
