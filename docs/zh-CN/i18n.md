# 文档国际化 (i18n) 规范

[English](../i18n.md) | [简体中文](i18n.md)

> 本文档定义本仓库所有文档的双语 (英文 / 简体中文) 规范.
> 每个新文档, 每个 PR, 每次清理都要遵守.

## 1. 范围

- **双语目标**: 英文 (默认) + 简体中文 (`zh-CN`).
- **每个文档** 在 `docs/`, workspace 里每个 `README.md`, 每个 crate 级别的
  `README.md`, 以及 OpenAPI spec, 都要遵守本规范.
- **英文优先原因**: GitHub 自动检测 `docs/<name>.md` (英文) 跟
  `docs/zh-CN/<name>.md` (中文) (基于 viewer 浏览器 `Accept-Language` 头).
  源真值 (source of truth) 是英文.

## 2. 文件命名 + 目录结构

| 文件位置            | 语言     | 角色                                  |
|--------------------|----------|---------------------------------------|
| `docs/<name>.md`   | 英文     | 标准 / 默认                           |
| `docs/zh-CN/<name>.md` | 中文 | 翻译, 独立子目录                      |
| `docs/api/openapi.json` | 英文 | OpenAPI 英文版本                      |
| `docs/zh-CN/api/openapi.json` | 中文 | OpenAPI 中文版本                |
| `crates/<crate>/README.md` | 英文 | crate README (单文件)              |
| `crates/<crate>/README.zh-CN.md` | 中文 | crate README 中文 (同目录)       |
| `<name>.<other>.md` | 其他 locale | 未来 locale (de, ja, fr, ...)        |

**英文 + 中文 走子目录分离** (`docs/` + `docs/zh-CN/`):
- 优点: 大文档集 (35+ md) 不污染主目录, 中文子目录独立管理
- 优点: mkdocs-material `i18n` plugin 跟 `alternate_language` 直接支持
- 缺点: GitHub 浏览时不自动按 `Accept-Language` 切文件 (需要 `?lang=zh-CN` query 或 README 链接跳转)
- 缺点: 跨语言 link 维护稍复杂 (中文文件指英文文件要用 `../<name>.md`)

### 子目录布局

```text
docs/
├── README.md                          # 英文主索引
├── i18n.md                            # 英文 i18n 规范
├── tech-stack.md                      # 英文技术栈
├── ma-harness-arch-map.md             # 英文架构
├── conformance-design.md              # 英文 conformance 设计
├── macro-design.md                    # 英文 macro 设计
├── plugin-schema-v1.md                # 英文 plugin schema
├── benchmark-design.md                # 英文 benchmark 设计

│   ├── 000-day0.md
│   └── ...
├── api/
│   └── openapi.json                   # OpenAPI 英文
├── mkdocs.yml                         # mkdocs 配置
└── zh-CN/                             # 简体中文子目录
    ├── README.md                      # 中文主索引
    ├── i18n.md                        # 中文 i18n 规范
    ├── tech-stack.md                  # 中文技术栈
    ├── ma-harness-arch-map.md         # 中文架构
    ├── conformance-design.md          # 中文 conformance 设计
    ├── macro-design.md                # 中文 macro 设计
    ├── plugin-schema-v1.md            # 中文 plugin schema
    ├── benchmark-design.md            # 中文 benchmark 设计
    ├── weekly/                        # 中文 weekly
    │   ├── 000-day0.md
```

**为什么不把 `weekly/`, `p11-*.md` 等 Tier 2 文档留英文在 `docs/`?**

- 它们是历史报告 / 周报, 主要受众是项目组内部
- 当前是中文为主, 业务方后续翻译成英文 (Tier 2 → Tier 1 升级)
- 把它们集中到 `docs/zh-CN/` 让中文读者一目了然, 英文版翻译完成后移回 `docs/`

## 3. 文件顶部语言条

每个文档都以语言条开头 (英文 + 中文 两个文件都要):

**英文版** (`docs/<name>.md`):

```markdown
# Title

[English](<name>.md) | [简体中文](zh-CN/<name>.md)

> Brief description.
```

**中文版** (`docs/zh-CN/<name>.md`):

```markdown
# 标题

[English](../<name>.md) | [简体中文](<name>.md)

> 简介.
```

**Banner 规则**:
- 第一行: 标题
- 第二行: 语言切换链接
- 英文文件链接到 `zh-CN/<name>.md` (下钻一级)
- 中文文件链接到 `../<name>.md` (上跳一级)

## 4. 翻译规则

### 4.1 术语表

| 英文              | 中文 (zh-CN)        | 备注                          |
|------------------|---------------------|------------------------------|
| workspace        | workspace           | 借用词, 不译                  |
| crate            | crate               | 借用词, 不译                  |
| conformance      | conformance (一致性测试) | 首次出现加括号              |
| plugin           | plugin (插件)       | 首次出现加括号                |
| bundle / manifest | bundle / manifest (清单) | 首次出现加括号            |
| artifact         | artifact (产物)     | 首次出现加括号                |
| registry         | registry (注册表)   | 首次出现加括号                |
| event            | event (事件)        | 首次出现加括号                |
| session          | session (会话)      | 首次出现加括号                |
| agent            | agent (智能体)      | 首次出现加括号                |
| LLM / model      | LLM / model (大模型) | 首次出现加括号               |

首次出现后, 去掉括号. 代码标识符, 路径, URL, CLI 命令永不翻译.

### 4.2 代码块

- 代码块 (fenced) **永不翻译** — 两个语言保持完全一致.
- 行内 `code` 也不翻译.
- 文件名, 函数名, 类型名等不翻译.

### 4.3 链接

- 跨文档链接: 英文文件用 `[X](<name>.md)`, 中文文件用 `[X](../<name>.md)`.
- 外部链接 (GitHub, crates.io 等) 语言中立.

### 4.4 版本同步

更新文档时:

1. **先更新英文版** (源真值).
2. 同步改动到中文版.
3. 如果中文版滞后, 在中文版加 footer:
   `> 本文档可能落后于英文版本. 最后同步: YYYY-MM-DD.`

## 5. 双语范围

### Tier 1 (必须双语) — 当前已覆盖

- `README.md` (根, 英文) + `docs/zh-CN/README.md` (根, 中文)
- `docs/` 里 8 个核心设计文档 + i18n 规范
- `crates/<crate>/README.md` + `crates/<crate>/README.zh-CN.md` (同目录)
- `docs/api/openapi.json` (英文) + `docs/zh-CN/api/openapi.json` (中文)

### Tier 2 (当前中文为主, 在 `docs/zh-CN/`)

- `docs/zh-CN/weekly/*.md` — 周开发日志
- `docs/zh-CN/p11-*.md`, `docs/zh-CN/p12-*.md` — 里程碑报告
- `docs/zh-CN/dsh-benchmark-report.md` — dsh 等价报告
- `docs/zh-CN/benchmark-report-week11.md` — perf baseline
- `docs/zh-CN/conformance-report-week11.md` — conformance baseline
- `docs/zh-CN/pyo3-evaluation.md` — 技术选型
- `docs/zh-CN/code-mode-deferred.md` — 技术决策
- `docs/zh-CN/roadmap-phase-7.md`, `docs/zh-CN/roadmap-phase-11.md` — 历史路线
- `docs/zh-CN/decision-log.md` — 决策日志

这些文件加顶部标记:

```markdown
# 标题 (中文 / Chinese only)

[English](../<name>.md) — coming soon. 中文为主.

> (内容)
```

翻译时拆成 `docs/<name>.md` (英文) + `docs/zh-CN/<name>.md` (中文),
删掉 "coming soon" 标记, 移回 `docs/`.

## 6. OpenAPI spec

`docs/api/openapi.json` 跟 `docs/zh-CN/api/openapi.json` 是**独立两份**.
原因:

- OpenAPI 工具 (Swagger UI, Redoc, 代码生成器) 期望单语言 spec.
- 单文件双语 `description` 字段难 grep, 难工具化.
- 两份文件结构相同; 只 `summary` / `description` 不同.

CLI 命令 `mah open-api export` 重新生成英文 spec.
中文 spec 由独立脚本生成 (P13 计划) 翻译 `summary` / `description` 字段.

## 7. mkdocs 配置

`docs/mkdocs.yml` 把所有英文 doc 列在 nav 里. mkdocs-material 通过
`alternate_language: zh-CN` 自动从 `docs/zh-CN/` 切语言.
每个页面顶部导航带语言切换器 (header 右上角).

```yaml
theme:
  alternate_language: zh-CN
extra:
  alternate:
    - name: English
      link: /en/
      lang: en
    - name: 简体中文
      link: /zh-CN/
      lang: zh-CN
```

业务方装 `pip install mkdocs-material[i18n]` 后 `cd docs && mkdocs serve` 即可.

## 8. PR / 贡献 checklist

添加或更新文档时:

- [ ] 英文文件 `docs/<name>.md` — **源真值**
- [ ] 中文文件 `docs/zh-CN/<name>.md` — 翻译
- [ ] 两个文件顶部都有语言条
- [ ] 代码块, 路径, 标识符在两个文件完全相同
- [ ] 跨文档链接指向对应语言 (英文→zh-CN/, 中文→../)
- [ ] `docs/README.md` 索引更新 (如果新增文档)
- [ ] `docs/zh-CN/README.md` 索引同步更新
- [ ] mkdocs.yml nav 更新 (如果新增文档)

## 9. 示例

### 好 — Tier 1 双语对

```text
docs/conformance-design.md         (英文, 源真值)
docs/zh-CN/conformance-design.md   (中文, 翻译)
```

两个文件都以:

**英文**:
```markdown
# Conformance Test Design

[English](conformance-design.md) | [简体中文](conformance-design.md)
```

**中文**:
```markdown
# Conformance Test Design (中文 / 简体中文)

[English](../conformance-design.md) | [简体中文](conformance-design.md)
```

### 好 — Tier 2 (当前中文为主)

```markdown
# Week 11 Conformance Report (中文 / Chinese only)

[English(conformance-report-week11.md) — coming soon. 中文为主.

> 本文档记录 Week 11 的 conformance 跑分.
```

### 差 — 命名不一致

```text
# 差: 同目录
docs/conformance-design.zh-CN.md

# 差: 错误子目录
docs/cn/conformance-design.md
```
