## spec 阶段学到的经验 (写到 memory)

- **大决策要 spec 先,代码后**: 5 份 spec 文档 (60KB) 凝固了"为什么",后面 12 周写代码不返工
- **trunk-based + 短 commit message**: 8 commit 都很小 (< 500 行),review 友好
- **决策矩阵化**: decision-log §5.1 的 8 crate × 公开性矩阵,比散在多处的文字描述更易查
- **跟参照系 (dsh) 划清的"硬线"清单**: arch-map §10 的 8 条红线,后面代码 review 时直接对照

## 跟 user 的协作模式 (今日确认)

- **commit 频率**: 每个决策点一个 commit,主题行 ≤ 72 字符,body 解释 why
- **review 节奏**: 我写一段,user 看一眼,有意见就改,无意见就继续
- **决策机制**: 大决策 user 拍板 ("你看着办" / 选推荐 / 给具体值),小决策我直接走
- **进度汇报**: 每小时 1 次,gate-discipline 静默 (无进展不打扰)
- **不 redo**: 决策落档后改一次要走新 commit + 更新 spec,不改老文档
