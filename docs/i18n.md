# Documentation Internationalization (i18n) Convention

[English](i18n.md) | [简体中文](i18n.zh-CN.md)

> This document defines the bilingual (English / Simplified Chinese) convention for
> all documentation in this repository. Apply this to every new doc, every PR, and
> every cleanup pass.

## 1. Scope

- **Bilingual target**: English (default) + Simplified Chinese (`zh-CN`).
- **Every doc** in `docs/`, every `README.md` in workspace, every crate-level
  `README.md`, and the OpenAPI spec must follow this convention.
- **Why English first**: GitHub auto-detects `*.md` (English) and `*.zh-CN.md` (Chinese)
  when the viewer has a matching browser language. Source of truth is English.

## 2. File naming

| File pattern            | Language     | Role                                  |
|-------------------------|--------------|---------------------------------------|
| `name.md`               | English      | Canonical / default                   |
| `name.zh-CN.md`         | Chinese      | Translation of the same content       |
| `name.zh-CN.md.json`    | (n/a)        | Reserved (used by some static sites)  |
| `name.<other>.md`       | Other locale | Future locales (de, ja, fr, ...)      |

Both files live in the **same directory** (do NOT split into `docs/` + `docs/zh-CN/`).
GitHub will display the right one based on the viewer's `Accept-Language` header.

### Examples

```text
docs/README.md                # English index
docs/README.zh-CN.md          # Chinese index
crates/ma-harness-core/README.md      # English crate README
crates/ma-harness-core/README.zh-CN.md # Chinese crate README
docs/api/openapi.json         # English OpenAPI
docs/api/openapi.zh-CN.json   # Chinese OpenAPI
```

## 3. Top-of-file language banner

Every translated file starts with a banner linking the other language:

```markdown
# Title

[English](name.md) | [简体中文](name.zh-CN.md)

> Brief description.
```

**Banner rules**:
- First line is the title.
- Second line is the language switcher link, immediately after the title.
- The link text must match the file being read (e.g. on a `.zh-CN.md` file, the
  link text is `[English](name.md)`, and on the English file it is `[简体中文](name.zh-CN.md)`).

## 4. Translation rules

### 4.1 Terminology

| English              | Chinese (zh-CN)        | Notes                          |
|----------------------|------------------------|--------------------------------|
| workspace            | workspace              | Borrowed; no translation       |
| crate                | crate                  | Borrowed; no translation       |
| conformance          | conformance (一致性测试) | First occurrence parenthetical |
| plugin               | plugin (插件)          | First occurrence parenthetical |
| bundlle / manifest   | bundle / manifest (清单) | First occurrence parenthetical |
| artifact             | artifact (产物)        | First occurrence parenthetical |
| registry             | registry (注册表)      | First occurrence parenthetical |
| event                | event (事件)           | First occurrence parenthetical |
| session              | session (会话)         | First occurrence parenthetical |
| agent                | agent (智能体)         | First occurrence parenthetical |
| LLM / model          | LLM / model (大模型)   | First occurrence parenthetical |

After the first occurrence, drop the parenthetical. Code identifiers, paths,
URLs, and CLI commands are never translated.

### 4.2 Code blocks

- Code blocks (fenced) are **never translated** — keep them identical in both
  languages.
- Inline `code` is also never translated.
- File names, function names, type names, etc. are never translated.

### 4.3 Links

- Cross-doc links should be language-relative: in the English file use
  `[X](other.md)`, in the Chinese file use `[X](other.zh-CN.md)`.
- External links (GitHub, crates.io, etc.) are language-neutral.

### 4.4 Versioning

When updating a doc:

1. Update the English version first (it is the source of truth).
2. Mirror the change in the Chinese version.
3. If the Chinese version lags behind (e.g. business only has one translator),
   add a footer note in the Chinese file:
   `> 本文档可能落后于英文版本. 最后同步: YYYY-MM-DD.`

## 5. What is in scope for bilingual support

### Tier 1 (must be bilingual) — currently covered

- `README.md` (root, English) + `README.zh-CN.md` (root, Chinese)
- 7 core design docs in `docs/` (see `docs/README.md` index)
- 8 crate READMEs (every `crates/*/README.md` has a `.zh-CN.md` sibling)
- `docs/api/openapi.json` (English) + `docs/api/openapi.zh-CN.json` (Chinese)

### Tier 2 (Chinese-only for now, marked "EN coming soon")

- `docs/weekly/*.md` — weekly dev logs
- `docs/p11-*.md`, `docs/p12-*.md` — milestone reports
- `docs/dsh-benchmark-report.md` — dsh equivalence report
- `docs/benchmark-report-week11.md` — perf baseline
- `docs/conformance-report-week11.md` — conformance baseline
- `docs/pyo3-evaluation.md` — tech evaluation
- `docs/code-mode-deferred.md` — tech decision
- `docs/roadmap-phase-7.md`, `docs/roadmap-phase-11.md` — historical roadmaps

These get a top-of-file banner:

```markdown
# Title (中文 / Chinese only)

[English](name.md) — coming soon. 中文为主.

> (content)
```

When translating, split into `name.md` (English) + `name.zh-CN.md` (Chinese) and
remove the "coming soon" marker.

## 6. OpenAPI spec

`docs/api/openapi.json` and `docs/api/openapi.zh-CN.json` are kept as two
**independent** files (not a single bilingual spec). Rationale:

- OpenAPI tooling (Swagger UI, Redoc, code generators) expects a single locale
  per spec.
- Bilingual in a single `description` field hurts grep-ability and tooling.
- Two files share the same structure; descriptions differ only by language.

The CLI command `mah open-api export` regenerates the English spec. The Chinese
spec is generated by a separate script (planned P13) that translates the
`summary` / `description` fields.

## 7. mkdocs config

`docs/mkdocs.yml` lists all docs under the English section. The Chinese
counterparts (`.zh-CN.md`) live in the same directory and are picked up by
mkdocs' `i18n` plugin (see mkdocs-material `i18n` feature). Top navigation
in every page includes a language switcher.

## 8. PR / contribution checklist

When adding or updating a doc:

- [ ] File named `name.md` (English) — **source of truth**
- [ ] Sibling file `name.zh-CN.md` (Chinese) — translation
- [ ] Top-of-file language banner present in BOTH files
- [ ] Code blocks, paths, identifiers are identical in both
- [ ] Cross-doc links point to the matching language
- [ ] `docs/README.md` index updated (if adding a new doc)
- [ ] mkdocs.yml nav updated (if adding a new doc)
- [ ] (If you only updated one language) PR description notes the language
  lag and target sync date

## 9. Examples

### Good — bilingual pair

```text
docs/conformance-design.md         (English, source of truth)
docs/conformance-design.zh-CN.md   (Chinese, translation)
```

Both files start with:

```markdown
# Conformance Test Design

[English](conformance-design.md) | [简体中文](conformance-design.zh-CN.md)
```

### Good — Tier 2 (Chinese-only for now)

```markdown
# Week 11 Conformance Report (中文 / Chinese only)

[English](conformance-report-week11.md) — coming soon. 中文为主.

> 本文档记录 Week 11 的 conformance 跑分.
```

### Bad — inconsistent naming

```text
# Bad: split into subdirectory
docs/zh-CN/conformance-design.md
docs/conformance-design.md

# Bad: wrong locale code (should be zh-CN not zh)
docs/conformance-design.zh.md
```
